Security

SolarCORE holds customers' names, addresses, contact numbers and the locations of their homes and businesses. This page summarises how that data is protected and what the people running it should do.

Accounts and sign-in

  • Two steps to sign in: a password, then a 6-digit code sent to the account's email. A code is random, stored only as a keyed hash, valid for 10 minutes, and allows 5 tries.
  • Lockout: 5 wrong passwords lock the account for 15 minutes.
  • Passwords are stored as one-way hashes, never as text, and never written to logs or the audit trail.
  • Google sign-in checks that the token is from Google, for SolarCORE, unexpired, single-use and for a verified email.
  • New client accounts cannot sign in until an administrator approves them.
  • The built-in administrator must set its own password and a real email at first sign-in.
  • Idle sessions end after 30 minutes. Signing out is a protected action that a link on another site cannot trigger.

Who can see what

  • Every page and every data request checks the user's role on the server; hiding a button is never the only protection.
  • Clients are limited to the installations linked to their own account: on the map, in lists, analytics, PDF exports, photos and assistant answers. Their account decides this, not anything they type or put in a link.
  • A photo belonging to someone else's installation answers exactly like a photo that does not exist, so stepping through photo addresses reveals nothing.
  • The public map shows anonymous density in roughly 1 km squares, never a site's location, name or owner.
  • Deleting installations, managing accounts and reading the audit trail are for administrators only.

Web protections

  • CSRF tokens on every form and every change, so another website cannot act on a signed-in user's behalf.
  • Parameterised SQL everywhere: values typed by users are never inserted into database queries as text.
  • Session cookie: HttpOnly (page scripts cannot read it), SameSite=Lax, and Secure over HTTPS.
  • Security headers on every response:
    HeaderStops
    X-Content-Type-Options: nosniffThe browser guessing a file's type, e.g. running an upload as a script.
    X-Frame-Options: DENYOther sites showing SolarCORE inside a frame to trick clicks.
    Referrer-Policy: strict-origin-when-cross-originPage addresses leaking to other sites.
    Strict-Transport-Security (HTTPS only)Browsers falling back to unencrypted HTTP.
  • Only public/ is served. The settings file, code and project history cannot be downloaded.
  • Uploads are checked by their real content type (JPG, PNG, WebP only), limited to 5 MB, renamed randomly and stored outside the public folder.

Accountability

  • The audit trail records sign-ins (including failed and blocked ones), changes to installations with old and new values, account changes, imports and exports.
  • Entries are kept for two years, then removed by a scheduled script that records its own run.

For the people running SolarCORE

  • Keep secrets (database password, mail and AI keys) in .env or the platform's variables. Never in the code repository, chats or screenshots. If one leaks, change it at the provider.
  • Always use HTTPS on a real server, with APP_ENV=production.
  • Give each person their own account, and deactivate it the day they leave.
  • Back up daily and keep copies off the server, readable only by the people operating the system.
  • Limit server, database and hosting-dashboard access to named people, and keep a list of who has it.

Data privacy (RA 10173)

The Philippine Data Privacy Act of 2012 applies to the personal data in SolarCORE. In practice:

  • Use the data only to run the service and evaluate it; report aggregates (counts, capacity), not customer names or addresses.
  • Record where the data is hosted and who can access it.
  • Agree in writing with the company what happens to the data when a pilot or contract ends: handed over, or deleted including every backup copy.

To report a security problem, contact the SolarCORE team directly rather than posting it publicly.
